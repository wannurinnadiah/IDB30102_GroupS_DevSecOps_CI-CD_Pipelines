# 2.4 Summary Table of Related Studies. 

| Year | Author(s) | Objective / Problem | Methods | Key Findings. | Limitations / Research Gaps. |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 2024 | Esposito, M. | Compare vulnerability detection performance across static application security testing (SAST) tools | Comparative benchmarking of SAST tools | Individual SAST tools generate varying numbers of vulnerabilities across different codebases | No single tool provides consistently complete coverage; motivates multi-tool comparison |
| 2023 | Cruz, D. B., Almeida, J. R., & Oliveira, J. L | Compare open-source vulnerability assessment solutions | Multi-tool SAST/DAST/SCA comparative pipeline | Integrating multiple security testing tools broadens vulnerability coverage | Multi-scanner pipelines introduce severe execution overhead |
| 2026 | Rida, A. | Evaluate execution overhead of automated security testing in a proxy CI/CD pipeline | Proxy CI/CD pipeline architecture with automated quality gate enforcement | Automated security testing accounts for up to 41.8% of total pipeline execution time | Overhead cost is severe enough to discourage full-tool adoption; no adaptive mechanism to reduce it |
| 2025 | De Vito, G., Palomba, F., & Ferrucci, F. | Study prevalence and remediation of security smells in Infrastructure-as-Code (IaC) scripts | Static analysis using custom IaC linters and LLMs | Misconfigured permissions and untrusted imports are widespread; linters flag intentional test/mock configurations as false alerts | Context-blind detection generates false positives on benign test code |
| 2023 | Ebert, C., & Hochstein, L. | Examine developer friction from blocking security gates in DevOps practice | Practitioner-based analysis of DevOps workflows | Developers tend to disable or bypass security gates to meet sprint deadlines | Lacks quantitative measurement of bypass frequency or its downstream risk |
| 2025 | Cheenepalli, J., Hastings, J. D., Ahmed, K. M., & Fenner, C. | Assess DevSecOps adoption challenges and best practices among SMEs | Mixed-method survey based on TAM and DOI theory (405 SME professionals) | 68% of organisations adopted DevSecOps, but only 12% scanned on every commit; complexity is the main barrier | Survey-based and self-reported; limited to SME context only |
| 2026 | Kandadi, A., Muntean, C. H., Gupta, S., & Bhaskaran, R. | Detect cloud-native CI/CD threats with sub-second latency | Hybrid Transformer + GNN ensemble on CICIDS-2017 dataset | 99.98% detection accuracy, 680 ms mean time to detect, 0.0005% false-positive rate | Tested on synthetic network flow data rather than native CI/CD audit logs |
| 2026 | Kalwani, T. | Predict vulnerabilities during CI/CD pipeline stages before build execution | Machine learning (Random Forest + RNN) on 416 commits | 93.8% detection accuracy; 83% reduction in scan latency | Small dataset (416 commits) may limit generalisability of the model |
| 2025 | Nagvekar, R. | Prevent CI/CD pipeline crashes and reduce test failures | Multi-agent LLM framework for autonomous remediation | Cut delivery cycle time by 35%, reduced errors by 40%, 95% remediation success rate | Scalability testing in large multi-tenant environments remains limited |
| 2024 | Abdiukov, T. | Review AI-based methods for security testing and compliance validation in DevSecOps | Conceptual literature review of AI applications across CI/CD stages | AI-based triage reduces false alarms compared to static rule-based engines | Narrative review with no original empirical trials; explainability of AI decisions remains unresolved |
| 2024 | Gangina, P. | Propose an AI/ML-driven architecture for compliance, testing, and threat detection in cloud-native DevSecOps | Conceptual synthesis of AI-supported detection and compliance frameworks | AI improves flaw identification and adapts to shifting compliance requirements | Conceptual only; cites secondary literature without original experiments |
